# SOP：找需求（选出第一个关键词）

| 项目     | 内容                                                                                                                                                                            |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 目的     | 从工具类后缀词出发，选出 1 个值得做成工具站的主关键词                                                                                                                           |
| 适用范围 | 新建工具站的选词阶段；不适用于内容站、品牌站                                                                                                                                    |
| 目标市场 | **美国**                                                                                                                                                                        |
| 不适用   | 刚冒头的热词（会被 H1/H6 淘汰），走 skill `hot-keywords`                                                                                                                        |
| 执行人   | 1 人                                                                                                                                                                            |
| 数据源   | 三条路线见 4.1：**A** 关键词规划师（需在 Google Ads 填账单信息）；**B** DataForSEO API（付费，全自动）；**C** Semrush / Ahrefs 免费额度手动查（不花钱、不绑卡）                 |
| 其他工具 | Google 搜索（无痕窗口，地区设为美国）、Google Trends；免费复核用 Ahrefs Keyword Generator、Semrush 免费额度                                                                     |
| 数据口径 | 关键词规划师没有 KD，搜索量常为区间；DataForSEO 的 KD 和 Semrush 不可直接对比。H2 的 29 是沿用值，需按第 8 节校准                                                               |
| 来源     | 哥飞《养网站防老第 1 步，挖掘出第 1 个需求》，阈值和异常处理为本 SOP 补充                                                                                                       |
| 自动化   | Claude Code skill `evergreen-keywords`（本文件所在 skill）；脚本是 TypeScript，用 Node 24 直接运行（`node <脚本>.ts`），不用装依赖；改阈值时同步改 `scripts/screen.ts` 顶部常量 |
| 词库     | 项目根目录 `research/pool.csv`，用 `node scripts/pool.ts` 维护（见 4.10）                                                                                                       |

---

## 1. 输入与输出

**输入**

- 词源（见 4.0）：后缀词清单（附录 A，每轮取 10 个）、对手已有排名的词、Search Console、相邻工具、热词转长青，以及词库里到期复查的词（`node scripts/pool.ts due`）
- 本 SOP 的阈值表（第 2 节）

**输出**

- `keyword-research-YYYYMMDD.csv`：本轮所有查过的词及判定结果（模板见附录 B）
- 1 个**选定主词**，附一句话理由，并写好选词简报 `briefs/<主词>.md`（见 4.10），交给 site-starter 建站
- 本轮结果合并进词库 `research/pool.csv`
- 如果本轮没有选出主词：一行结论，写明卡在哪一关

---

## 2. 阈值表

硬性条件：任意一条不满足即淘汰。软性条件：用于候选词之间排序。

| 编号 | 条件                         | 阈值                                                                                                                                                                                                                                                                                                       | 类型 |
| ---- | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| H1   | 主词美国月搜索量             | **≥ 5,000**；区间跨过 5,000（如 1K–10K）记 `unsure`，需复核                                                                                                                                                                                                                                                | 硬性 |
| H2   | 主词 KD                      | ≤ 29（待校准）。**数据源没有 KD 时跳过，4.4 实搜必须做**                                                                                                                                                                                                                                                   | 硬性 |
| H3   | 主词 CPC                     | ≥ $0.10（关键词规划师取首页出价高低区间的中值；没有出价数据视为不通过）                                                                                                                                                                                                                                    | 硬性 |
| H4   | 可变现                       | 能放广告**或**能接支付（见 4.3）                                                                                                                                                                                                                                                                           | 硬性 |
| H5   | 搜索结果首页强对手数         | 前 10 名中强对手 ≤ 3 个（定义见 4.4）                                                                                                                                                                                                                                                                      | 硬性 |
| H6   | 趋势                         | 三条都要满足：① 近 12 个月月度最高/最低 < 3；② 近 12 个月均值比前 12 个月跌幅不超过 50%；③ **最近 3 个月比去年同期的变化，相对后缀词本身（基线）多跌不超过 20%**，例如 calculator 跌 23%、gravel calculator 跌 33%，相对只多跌 13%，通过。①② 可用导出数据初判，③ 必须用 Google Trends 数据和基线（见 4.7） | 硬性 |
| H7   | 合规                         | 主流意图不属于灰色用途（见 4.6）                                                                                                                                                                                                                                                                           | 硬性 |
| S1   | 关键词变种数（月搜 ≥ 50 的） | 越多越好，≥ 20 个为佳                                                                                                                                                                                                                                                                                      | 软性 |
| S2   | CPC                          | 越高越好，≥ $1 为佳                                                                                                                                                                                                                                                                                        | 软性 |
| S3   | 首页结果中「内页」占比       | 越高越好                                                                                                                                                                                                                                                                                                   | 软性 |
| S4   | 有 AI 改造空间               | 有加分                                                                                                                                                                                                                                                                                                     | 软性 |

> 阈值是起始值。跑完 3 轮后，根据实际结果回头调整，并在第 8 节记录。

---

## 3. 时间限制

- 每个后缀词：**≤ 20 分钟**
- 每轮：10 个后缀词，**≤ 1 个工作日**
- 一个候选词深入检查（第 4.3–4.7 步）：**≤ 15 分钟**

超时就记录当前结论并跳到下一个，不要为单个词停留。

---

## 4. 操作步骤

### 4.0 词从哪里来

每轮先定这一轮的词源，可以混用。来源写进结果 CSV 的 `seed` 列（后缀词直接写词，其他来源写 `来源:名字`），合并进词库时会保留。

| 来源                | 怎么拿                                                                                                                       | 适合什么时候                                                   | 词库里的 source   |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- | ----------------- |
| 1. 后缀词           | 附录 A，`dfs.ts keywords <后缀词>` 或关键词规划师导出                                                                        | 没有方向时的基本盘                                             | `suffix:<后缀词>` |
| 2. 对手已有排名的词 | `dfs.ts ranked <对手域名>`：对手网站上真的带来流量的词                                                                       | 已经知道一批做得好的工具站（例如 convertcase.net、ipvoid.com） | `ranked:<域名>`   |
| 3. Search Console   | 已上线网站的"查询"报告导出，再 `dfs.ts overview --from <导出>` 补搜索量和 KD                                                 | 有站在跑；展示多但还没有专门页面的查询                         | `gsc:<站点>`      |
| 4. 相邻工具         | 竞品分析和建站时发现的同类需求（例如做 remove duplicate lines 时发现的 sort lines alphabetically），`dfs.ts overview` 查数据 | 每次竞品分析之后                                               | `adjacent:<站点>` |
| 5. 热词转长青       | 热词站上线 30 天日均点击 ≥ 10（热词 SOP 4.5），按本 SOP 补查                                                                 | 热词站转入长青维护时                                           | `hot:<来源>`      |

**词库里到期复查的词也是这一轮的输入**：`node scripts/pool.ts due` 列出到了复查日期的词（例如 90 天前因为趋势被刷掉的词），用 `dfs.ts overview` 重新拉数据再筛一遍。

### 4.1 初筛

**路线 A：关键词规划师（需绑卡）**

1. 打开 ads.google.com → 工具 → 关键词规划师 → 「发现新关键字」。**前提：Google Ads 账号已填写账单信息并完成开户**（不投放广告也必须填）；没有在投的广告系列就不产生费用
2. 输入后缀词，**地区：美国**，**语言：英语**，搜索网络：Google
3. 「下载关键字提示」→ 选 **.csv**，存到 `research/raw/<后缀词>-YYYYMMDD.csv`（文件是 UTF-16 + 制表符分隔，不用转换）
4. 筛选：
   ```bash
   node <skill-dir>/scripts/screen.ts research/raw/<后缀词>-YYYYMMDD.csv --seed <后缀词> --out research/keyword-research-YYYYMMDD.csv
   ```
5. 结果是 `unsure`（区间跨过 5,000）的词，进入 4.2 之前先复核：用 Ahrefs 免费 Keyword Generator 或 Semrush 免费额度查确切搜索量

**路线 B：DataForSEO（付费，全自动）**

1. 拉取包含后缀词的美国关键词（服务端已按 Volume ≥ 5,000 过滤、按搜索量降序）：
   ```bash
   node <skill-dir>/scripts/dfs.ts keywords <后缀词> --min-volume 5000 --max-volume 30000 --out research/raw/<后缀词>-YYYYMMDD.csv
   # 大后缀词不加 --max-volume，前 1,000 个全是头部大词
   ```
2. 套用 H1/H2/H3 和 H6 的 12 个月波动比：
   ```bash
   node <skill-dir>/scripts/screen.ts research/raw/<后缀词>-YYYYMMDD.csv --seed <后缀词> --out research/keyword-research-YYYYMMDD.csv
   ```
3. 每次调用的花费会打印出来，记到本轮总花费里

**路线 C：免费额度手动查（不绑卡）**

1. 用 Semrush 免费账号的 Keyword Magic Tool（Database 选 US）和 / 或 Ahrefs 免费 Keyword Generator（Country 选 United States）查后缀词。免费额度每天很少，先查最需要的
2. 把看到的结果原样复制给 agent（或自己填），整理成 `research/raw/<后缀词>-YYYYMMDD.csv`，列：`Keyword,Volume,Keyword Difficulty,CPC (USD),Source`；查不到的值留空
3. 交给 `screen.ts`。没有趋势数据，H6 在 4.7 对最终候选人工看 Google Trends
4. 注意 Semrush 和 Ahrefs 的 KD 算法不同，同一个 CSV 里混用时在 `Source` 列标明来源，H2 只对 Semrush 的 KD 直接套用 29；Ahrefs 的 KD 记录下来，判断以 4.4 实搜为准

**所有路线共用**

- Semrush 等其他工具的导出，只要有 Keyword / Volume / Keyword Difficulty / CPC (USD) / Trend 列，也可以直接交给 `screen.ts`
- 结果为空 → 在 CSV 记一行「后缀词 / 初筛为空」，换下一个后缀词

6. 结果不为空 → **所有** `pending` 的词都进入后面的检查，不只取搜索量最大的前几个。`screen.ts` 已经把月搜 5,000 到 30,000 的中段排在前面：头部词大多是品牌词、侵权词和被 AI 直接回答的词，新站在中段才有机会。按顺序检查，每个后缀词最多深查 **10 个**（时间限制见第 3 节）
7. `screen.ts` 自动标成 `excluded` 的词（"4.2 auto"：线下服务、购物、下载别人的内容），在 4.2 里扫一眼确认，误判的改回来

### 4.2 快速排除（每个词 ≤ 1 分钟）

逐个看，满足任一条直接淘汰并在 CSV 记原因：

- 是品牌词、硬件型号、人名（如 `vasco translator m3`）
- 是找工作、找线下服务（`jobs`、`near me`）
- 一看就无法用网页工具满足的需求

剩下的进入 4.3。

### 4.3 变现检查（H4）

问两个问题，至少一个答「是」才通过：

- 这个词的页面能放 Google AdSense 吗？（成人、赌博、违法相关的不能放）
- 能设计一个付费功能吗？（批量处理、去水印、API、高级选项）

### 4.4 实搜检查（H5、S3）

1. 获取谷歌美国前 10 个**自然结果**：
   - 路线 A：无痕窗口、地区美国人工搜索（或 agent 用 WebSearch 估算后人工抽查）
   - 路线 B：`node <skill-dir>/scripts/dfs.ts serp "<主词>"`，同时给出各域名月自然流量估算
2. 逐个看结果，在 CSV 记录：
   - 域名
   - 是首页还是内页
   - 页面是否**专门**为这个词做的（标题含主词，且页面主体就是这个工具）
3. **强对手定义**：同时满足以下两条：
   - 域名是大站：路线 B 用月自然流量估算 ≥ 50,000（`strong_domain=yes`，待校准）；路线 A 按常识判断（政府、主流媒体、平台型网站、头部工具站），拿不准标 `unsure`
   - 页面是专门为这个词做的（脚本的 `title_has_keyword` 只是线索，要看页面主体是不是这个工具）
4. 强对手 > 3 → 淘汰（H5）
5. 记下首页结果中「内页」的数量（S3）

> 例：`meme generation` 的 KD 只有 26，但第一名是 time.com，说明工具数据和实际结果可能不一致，**以实搜为准**。

### 4.5 同义说法检查

1. 查这个需求最常见的 2–3 种说法（路线 A：在关键词规划师里一起输入；路线 B：`dfs.ts keywords "<说法>"`）（如 `meme generation` 与 `meme generator`）
2. 记下每种说法的搜索量和 KD
3. 如果搜索量最大的说法 KD ≥ 60：
   - 不直接淘汰
   - 但在 CSV 备注「主流说法难度高」，排序时降一档

### 4.6 合规检查（H7）

1. 把主词 + 下拉推荐词交给 AI，提问：「逐个分析这些词的搜索意图」
2. 如果主流意图属于以下任一类 → 淘汰：
   - 绕过平台验证、批量注册小号
   - 伪造证件、伪造身份信息
   - 侵犯版权（下载付费内容等）
   - 其他明显违反平台政策或法律的用途
3. 意图混杂（例如既有测试数据，也有绕过验证）→ 只有能把页面定位为合法用途时才通过，并在 CSV 备注

### 4.7 趋势检查（H6）

1. `screen.ts` 已按导出里的月度数据和 YoY 列做初判（①②）。导出只有 12 个月数据，**算不了 ③**，所以对进入 4.7 的每个候选都要做下面几步
2. 拿 Google Trends 数据（美国、近 5 年），**主词和它的后缀词（基线）各一份**：
   - 路线 B：`node <skill-dir>/scripts/dfs.ts trends "<主词>" --out research/raw/trends-<主词>-YYYYMMDD.csv`，基线同样跑一次（例如 `"calculator"`）
   - 其他路线：打开 Google Trends，地区 United States，时间 Past 5 years，分别搜主词和后缀词；点「Interest over time」右上角的下载图标，存到同样的路径
   - 来源不是后缀词时（对手排名词、Search Console），基线用这个词所属的工具大类（例如 "converter"、"generator"），在 CSV 备注里写明
3. 计算三条：
   ```bash
   node <skill-dir>/scripts/trends.ts --baseline research/raw/trends-<后缀词>-YYYYMMDD.csv research/raw/trends-<主词>-YYYYMMDD.csv
   ```
   脚本把周数据按月平均，去掉当前未满的月份。基线本身跌超过 40% 时，脚本会标出"category declining"：整个大类在萎缩，照样按相对跌幅判断，但在选定理由里写明
4. 任一条不满足 → 淘汰：
   - ① 近 12 个月最高/最低 ≥ 3：季节性或热点
   - ② 近 12 个月均值比前 12 个月跌了一半以上：需求在萎缩
   - ③ 最近 3 个月的跌幅，比基线多跌超过 20%：这个词**比同类下滑得更快**（常见原因是 AI 概览或 AI 助手直接替代了这个工具）。整类工具词都在跌时，不再一刀切全部淘汰
5. 导出给的搜索量是过去一段时间的平均值。③ 跌幅很大时，当前的实际搜索量会明显低于导出数字，H1 也可能已经不成立

### 4.8 扩展检查（S1、S2、S4）

1. 记下主词的变种数量（S1）：路线 A 在关键词规划师里用主词再导出一次，数搜索量下限 ≥ 50 的行；路线 B 用 `dfs.ts keywords "<主词>" --min-volume 50 --limit 1000` 数行数
2. 记下 CPC（S2）
3. 想一个 AI 改造点并写一句话（S4），例如：「用户用自然语言描述需求，AI 直接生成结果」

### 4.9 选定

1. 通过全部硬性条件的词进入候选
2. 按软性条件排序：S1 > S2 > S3 > S4
3. 取第一名为选定主词，在 CSV 标记 `selected`，写一句理由
4. 选定后**当天**查域名（见附录 C），能注册就立刻注册

### 4.10 词库和选词简报

1. 本轮结束时把结果合并进词库：
   ```bash
   node scripts/pool.ts merge research/keyword-research-YYYYMMDD.csv
   ```
   词库按淘汰原因自动定复查日期：趋势（H6）90 天，搜索量（H1）180 天，强对手（H5）120 天，`unsure` 7 天，`candidate` 14 天，`queued` 立刻到期（下一轮先查）；变现（H4）、合规（H7）和 `excluded` 不再复查
2. 平时想到的词、建站时发现的相邻工具，随手加进词库：`node scripts/pool.ts add --source adjacent:<站点> "<词>"`
3. 选定主词后，按附录 D 写选词简报 `briefs/<主词>.md`。它是交给 site-starter 的唯一入口：新网站把它复制成 `docs/keyword-brief.md`，竞品分析和关键词分析从它开始，不用再查一遍数据

## 5. 异常处理

| 情况                                   | 处理                                                                                             |
| -------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 一整轮 10 个后缀词都没有候选           | 换下一批 10 个后缀词。连续 2 轮都没有 → 回到 4.1，改用 **Related** 标签代替 Broad Match 再跑一遍 |
| 多个候选打分相同                       | 选 CPC 更高的；再相同，选搜索结果首页内页更多的                                                  |
| API 数据和实搜明显矛盾                 | 以实搜为准，在 CSV 备注                                                                          |
| 主词通过，但主流说法 KD 很高           | 可以做，页面同时覆盖两种说法；首页先优化低 KD 的说法                                             |
| 主词的 .com 和带横杠的 .com 都被注册了 | 按附录 C 的顺序继续，不要因为域名放弃一个好词                                                    |
| 某条判断拿不准                         | 标记 `unsure` 并写原因，不卡流程，在 4.9 排序时降一档                                            |

**不允许**为了让某个词过关而临时放宽 H1（月搜 5,000）。
