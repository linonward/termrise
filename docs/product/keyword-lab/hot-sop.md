# SOP：抢热词（48 小时上线一个热词工具站）

| 项目           | 内容                                                                                 |
| -------------- | ------------------------------------------------------------------------------------ |
| 目的           | 发现刚冒头的新需求，在首页还空着时用一个单页工具站抢占                               |
| 和长青词的关系 | 独立的第二条线，阈值不同，**不要**套用 skill `evergreen-keywords` 的 SOP 的 H1/H2/H6 |
| 目标市场       | 美国                                                                                 |
| 投入上限       | **1 人天**（8 小时，含评估）+ **1 个域名**                                           |
| 时限           | 从发现到上线 **≤ 48 小时**，超时放弃                                                 |
| 自动化         | Claude Code skill `hot-keywords`（本文件所在 skill）；脚本在同目录下 `scripts/`      |

---

## 1. 输入与输出

**输入**

- 热词来源（第 4.1 步）
- 发现时间（记为 T0）

**输出**

- `research/hot-keywords.csv` 追加一行（模板见附录 A）
- 结论二选一：
  - `go`：选定的词、工具做什么、域名，以及上线截止时间（T0 + 48h）
  - `drop`：卡在哪一条

---

## 2. 阈值表

| 编号 | 条件               | 标准                                                                         | 类型           |
| ---- | ------------------ | ---------------------------------------------------------------------------- | -------------- |
| T1   | **不含商标**       | 词里不含任何第三方的品牌、产品名、公司名、AI 模型名、人名、影视/游戏/动漫 IP | 硬性           |
| T2   | 合规               | 主流意图不属于灰色用途（同长青 SOP 4.6）                                     | 硬性           |
| T3   | 首页还空着         | 谷歌美国前 10 个自然结果里，**专门为这个词做的工具页 ≤ 1 个**                | 硬性           |
| T4   | 信号确认           | 至少 **2 个独立来源**同时出现这个需求（如 Trends + X，HN + Reddit）          | 硬性           |
| T5   | 一天做得完         | 单页工具，1 人天内能做出可用版本                                             | 硬性           |
| T6   | 可变现             | 能放广告，或热度过后能接付费功能                                             | 硬性           |
| T7   | 评估时限           | 从 T0 到给出 go/drop **≤ 2 小时**                                            | 硬性           |
| P1   | 热度过后还剩需求   | 热度退了以后，还会有人持续搜同类需求                                         | 软性（最重要） |
| P2   | 精确匹配域名可注册 | 关键词.com 或带横杠的 .com                                                   | 软性           |
| P3   | 有 AI 改造空间     | 能用 AI 做出差异化                                                           | 软性           |

**T1 的判断方法**：把词里的每个名词问一遍「这是不是某家公司或某个人的名字？」。拿不准就去 USPTO（tmsearch.uspto.gov）搜一下，有活跃注册就算商标。
**T1 的影响**：大量热词会因此被排除（新模型名、新 App 名、明星、电影）。剩下能做的主要是**新玩法、新格式、新概念**的通用说法。例如：做 `ai meme camera`，不做 `memecam`。

> 阈值是起始值。跑满 5 个热词后回头校准，改动记在第 8 节。

## 3. 时间线

| 时间       | 做什么                                                       | 耗时上限  |
| ---------- | ------------------------------------------------------------ | --------- |
| T0         | 发现苗头，记录来源和时间                                     | —         |
| T0 → T0+2h | 评估 T1–T7，给出 go/drop                                     | 2h        |
| go 之后    | 注册域名                                                     | 15 分钟   |
|            | 用 site-starter 建站，只做首页（选词简报 → 工具 → 首页内容） | ≤ 5h      |
|            | 部署（site-starter 上线清单的部署部分）                      | ≤ 30 分钟 |
|            | 提交 GSC 和 sitemap、跑 IndexNow，在爬虫常去的高频站点发链接 | ≤ 30 分钟 |
| ≤ T0+48h   | **上线**；超时 → `drop`，原因写「超时」                      | —         |

累计投入超过 8 小时，不管做到哪里都停：能上线就上线，不能就 `drop`。

## 4. 操作步骤

### 4.1 发现

每天固定扫一次（≤ 20 分钟）：

| 来源                       | 看什么                                           | 自动抓取 |
| -------------------------- | ------------------------------------------------ | -------- |
| Google Trends 美国每日热搜 | 有没有不是人名、赛事、新闻的「新玩法、新概念」   | ✅ RSS   |
| Hacker News 首页           | 新工具、新格式、新标准                           | ✅ API   |
| GitHub Trending            | 新出现的开源工具，有没有「网页版」需求           | ✅       |
| Google Trends 探索页       | 对候选词看「相关查询 → 上升」，是否出现 Breakout | ❌ 手动  |
| X、Reddit、Product Hunt    | 大家在转发、讨论的新玩法                         | ❌ 手动  |

```bash
node <skill-dir>/scripts/hot-sources.ts
```

### 4.2 转成搜索词

热点本身往往不是搜索词。要想清楚：**用户会在谷歌里搜什么来完成这件事？**

- 热点是「某种新的图片风格火了」→ 搜索词可能是 `<风格名> generator`、`turn photo into <风格名>`
- 用 `suggest.ts` 看下拉推荐词里有没有这个说法：已经出现，说明有人在搜；没出现，说明还太早，或者大家不这么说

```bash
node <skill-dir>/scripts/suggest.ts "<候选词>"
```

### 4.3 评估（≤ 2 小时）

按顺序检查，任一条硬性条件不过就立即 `drop`，不再往下看：

1. **T1 商标**：先查这一条，最快排除
2. **T2 合规**：看下拉推荐词里的意图
3. **T4 信号**：记下两个独立来源的链接
4. **T3 首页**：谷歌无痕窗口、地区美国，数前 10 名里专门的工具页
5. **T5 一天能做完**：用一句话写出工具做什么；写不出来，或者需要后端、账号体系、大模型训练 → 不过
6. **T6 变现**：同长青 SOP 4.3
7. 软性条件：写一句 P1 的判断（热度退了以后，还剩什么需求）

### 4.4 Go / Drop

- 硬性条件全过 → `go`，在 CSV 写清截止时间
- 同时有多个 `go`：先比 P1（退热后的剩余需求），再比 P2（域名）
- 一次只做一个热词站，做完再做下一个

### 4.5 上线后

| 时间点      | 检查                 | 决定                                                                                                            |
| ----------- | -------------------- | --------------------------------------------------------------------------------------------------------------- |
| 上线 +1 天  | `site:域名` 是否收录 | 没收录 → 再发一轮外链                                                                                           |
| 上线 +7 天  | GSC 展示量、点击量   | 只记录，不做决定                                                                                                |
| 上线 +30 天 | 近 7 天日均点击      | **≥ 10** → 转入长青维护：按长青 SOP 补做 H5、H6 检查，开始补内页。**< 10** → 停止投入，网站保持在线，不再花时间 |

## 5. 异常处理

| 情况                                 | 处理                                                |
| ------------------------------------ | --------------------------------------------------- |
| 词刚冒头，下拉推荐里还没有           | 记为 `watch`，24 小时后复查一次。还没有 → `drop`    |
| 评估中途发现商标问题                 | 立刻 `drop`，不要换个拼法绕过去                     |
| 搜索结果首页在评估期间被占满         | `drop`，在 reason 写「已被抢」                      |
| 第 4.3 步过了，但已经花了 2 小时以上 | 仍然算 `drop`（T7）；可以记为 `watch`，第二天再看   |
| 做到一半发现 1 天做不完              | 砍功能，保证能在 48 小时内上线；砍到不可用 → `drop` |
| 30 天时点击在 5–10 之间              | 再观察 30 天，期间不追加投入                        |
