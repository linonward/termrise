# ADR-007: i18n — next-intl without Locale Prefix

- Status: Accepted
- Date: 2026-10-05

## Context

首批用户包括英文和中文用户，第一版就要支持 English 和简体中文。第一版不值得为多语言 URL 做路由和 SEO 设计。

## Decision

- 使用 next-intl，文案全部放在 `apps/web/messages/{en,zh}.json`，组件不硬编码用户可见字符串。
- URL 不带 locale 前缀。Locale 依次取 `NEXT_LOCALE` cookie → `Accept-Language` → `en`。
- API 错误 message 保持英文，前端按 `error.code` 显示本地化文案。
- 测试检查两个语言文件的 key 集合一致。

规则细节见 [Internationalization](../product/ux.md#internationalization)。

## Alternatives

- **Locale 前缀 URL（`/zh/...`）**：利于 SEO，但所有路由、链接、重定向、OAuth 回调都要带前缀。需要时再做。
- **只做英文**：中文用户是首批目标之一。新产品不需要中文时，可以只保留 `en`。

## Consequences

- 同一 URL 对不同用户显示不同语言，搜索引擎只会索引英文版本。
- 日后加前缀时，路由需要整体迁移到 `[locale]` 段。
